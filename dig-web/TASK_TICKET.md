# 💡 UX & 컨텐츠 업데이트 작업 가이드

이 문서는 Streamlit 기반 무대소환 사업계획서 어플리케이션(Task C)의 네비게이션, 화면 레이아웃, 에러 핸들링 경험을 개선하기 위한 프론트엔드 작업 지침입니다.

---

## 1. 목적 및 목표 (Context & Goals)
본 작업의 주 목적은 다음과 같습니다:
1. 불필요한 공통 네비게이션 메뉴 **"AI 버전 관리자 설정"** 삭제
2. 특정 2개 화면( **"전체 제출 내용 보기 탭 📝 세부 사업 계획 (Step 3)"**, **"AI예비진단(접수자용)"**)의 레이아웃과 문구 톤앤매너를 기존 **"5. AI버전 관리자 설정"** 화면의 타이포그래피, 여백, 구조와 완벽히 동일하게 맞추는 평탄화 작업
3. Gemini API 한도 초과(HTTP 429 Quota Exceeded) 에러 발생 시, 0점이나 평가 불가 상태가 마치 정상적인 평가 결과인 것처럼 보이는 UI를 수정하여 명확한 에러 메시지와 재시도 안내를 제공하는 UX 개선

## 2. 네비게이션 업데이트: 메뉴 삭제
* **삭제 대상 메뉴 라벨**: `"AI 버전 관리자 설정"` (띄어쓰기 변형 `"AI버전 관리자 설정"` 포함)
* **삭제 위치**: 
  * 좌측 글로벌 사이드바 네비게이션(`st.sidebar` 등)
  * 경우에 따라 존재하는 모바일 접속용 햄버거 메뉴 내장 링크
* **검색 및 제거 대상 범위**:
  * 메인 앱 엔트리포인트 (`app.py` 또는 `main.py`)
  * 네비게이션 라우팅 및 탭 설정 관련 코드
  * 사용자 접근 권한(Role permissions) 목록
  * 관련 정적 텍스트/언어 리소스 (한국어)
* **제거 후 필수 조치 사항**:

## 5. Gemini API 한도 초과 오류 처리 (Error Handling UX)

* **현재 문제**: Gemini API(429 Quota Exceeded) 에러 발생 시, 비정상 상태임에도 불구하고 숫자 `0점`이나 `평가 등급: N/A / 불가 판단`이 마치 실제 평가 결과인 것처럼 카드 UI에 로드되어 사용자 혼란 유발.
* **요구 사항**: 429 에러 감지 시, 평가 결과 카드를 숨기고 명시적인 **에러 상태 전용 카드(Alert 상태)**를 렌더링해야 합니다. 숫자 스코어를 노출해서는 안 됩니다.

#### 📌 UI 텍스트 명세 (Error State)
* **카드 타이틀**: `2. 4대 평가 지표 분석 스코어` (유지)
* **스코어 표시**: `Total: —` (또는 `N/A`)
* **평가 상태 (Status)**: `평가 등급: N/A`
* **에러 세부 안내문 (적색 글씨/Alert 컴포넌트)**: 
  > `"🚨 평가 불가 — Gemini API 사용 한도 초과(429). 나중에 다시 시도해 주세요."`
* **툴팁 (Hover Text) 또는 부가 설명**: 
  > `"서버가 잠시 과부하 또는 할당량 초과 상태입니다. 관리자에게 문의하거나 일정 시간 후 재시도하세요."`
* **버튼 (선택사항, 벡엔드 연동 시)**: `[다시 시도]`

#### 📌 동작 가이드 (개발 참고용)
* **재시도 로직**: 즉각적인 자동 재호출 폭탄(Infinite Loop)을 막기 위해 **지수 백오프(Exponential Backoff)**가 적용된 수동 `[다시 시도]` 버튼을 배치해야 합니다.
* **로깅 및 모니터링**: 429 에러 발생 시 콘솔 로깅에 에러 상세내용, 타임스탬프를 기록하고, 모니터링 시스템(구축되어 있을 경우)으로 Quota 에러 카운트를 전송해야 합니다.

## 6. QA 테스트 체크리스트 (QA Checklist)

* [ ] **메뉴 삭제 검증**: 데스크탑 및 모바일 뷰 모두에서 네비게이션 및 사이드바 내 "AI 버전 관리자 설정" 메뉴가 완전히 노출되지 않는지 확인.
* [ ] **라우팅 방어 검증**: 이전에 존재했던 "AI 버전 관리자 설정"의 URL 경로로 직접 접속 시도 시, 크래시 없이 대시보드로 리다이렉트 되며 "해당 메뉴는 더 이상 제공되지 않습니다." 플래시 메시지가 뜨는지 확인.
* [ ] **레이아웃 일치율 검증**: "전체 제출 내용 보기"와 "AI예비진단" 페이지의 폰트 사이즈, 마크다운 굵기, 요소별 상하 여백이 기존 "5. AI버전 관리자 설정" 레이아웃 문서와 시각적으로 동일한지 대조 확인.
* [ ] **카피라이팅 검수**: 제시된 템플릿(한국어 문구) 오탈자 여부 및 `**[항목명]**` 마진 간격 체크.
* [ ] **에러 핸들링 - 1 (Mocking Test)**: 코드로 강제 429 에러(Gemini Quota Exceeded) 유발 시, 기존 0점 출력 구조 대신 명시된 붉은색 알러트(Alert) 카드 UI가 정상 출력되는지 확인.
* [ ] **에러 핸들링 - 2 (스코어 노출 방지)**: 429 에러 상태에서 "Total: 0점" 등 숫자가 출력되지 않고 `Total: —` 혹은 `N/A`로 안전하게 폴백(Fallback) 되는지 확인.

## 7. 인수 조건 (Acceptance Criteria)
위의 작업이 완료 상태(Done)로 승인되기 위한 필수 충족 조건입니다.
* 모든 화면에서 "AI 버전 관리자 설정"으로 접근할 수 있는 UI 진입점이 0개여야 함.
